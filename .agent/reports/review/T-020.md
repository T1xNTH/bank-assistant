| `F-T020-01` | `major` | `src/app/security/pii.py:23`; `tests/security/test_pii.py:36-59` | Phone suffix assertion rejects a valid complete number when the next word begins with a digit. International contiguous phones cannot fall back to account masking due to the preceding plus sign; formatted phones may have no account-length group. Thus raw PII survives and types=[] can later bypass sensitive routing. | Fix contextual phone boundaries/segmentation with a conservative privacy policy; add public mask_text regression cases for amounts and adjacent independent numbers while preserving intended overlong-number negatives. Track ISSUE-021. | `teammate-b` |

Independent reproduction (synthetic values only), WSL Python 3.12, real presidio-analyzer 2.2.366, PYTHONPATH=src:

```python
from app.security.pii import mask_text
mask_text("+84900000001 100 VND")
# actual: ('+84900000001 100 VND', [])
mask_text("0900 000 001 100 VND")
# actual: ('0900 000 001 100 VND', [])
mask_text("+84900000001 10000001")
# actual: ('+84900000001 <ACCOUNT_NUMBER>', ['ACCOUNT_NUMBER'])
```

Expected: fully redact the phone and include PHONE_NUMBER, retaining the independent amount/account appropriately. Control `+84900000001, 100` returns `('<PHONE_NUMBER>, 100', ['PHONE_NUMBER'])`; `000000000001/10000001` returns both complete placeholders. Both unmasked examples were confirmed with independent assertions. The negative test `0900 000 001 2` checks only recognizer rejection; it does not test the privacy consequences of treating every following numeric word as an extension.
